# ADR-010: Definition of Done для беты

## Дата
2026-09-23

## Статус
Принято

## Контекст

За 6 дней активной работы (2026-09-18 … 2026-09-23) проект
прошёл путь от монолита к модульной архитектуре: 25 агентов,
613 тестов, Firefox bridge, KDE виджет, пауза медиа, hotkey.
Прод стабилен на systemd.

Но **нет формального критерия «бета готова»**. Каждый раз кажется,
что «ещё чуть-чуть» — и это «чуть-чуть» не заканчивается. Это
**антипаттерн**: без чёткого DoD проект либо выйдет сырым, либо
никогда не выйдет.

ADR-010 фиксирует: что считаем бетой и что не считаем.

## Что считаем бетой

Бета — это **версия для друзей и первых пользователей**. Не релиз,
не production, не «показать всему миру». Бета — для **5-10 человек**,
которые заинтересованы и готовы к сыростям.

## Обязательные критерии (Must Have)

Все 10 критериев должны быть выполнены. Без исключений.

### 1. Установка «в одну команду»

Пользователь (друг) должен уметь поставить Ауру на Arch Linux:
- `git clone` → `cd aura_project` → `./install.sh` → работает.
- `install.sh` — **создаём** в этой задаче. Проверяет зависимости,
  устанавливает venv, скачивает модели, регистрирует systemd-юнит.

**Критерий проверки:** друг ставит на **чистом** Arch (виртуалка)
без твоей помощи → работает.

### 2. README для пользователя

- Что это.
- Требования (Arch, Python 3.12, PipeWire, Ollama).
- Установка.
- Первый запуск (`aurа.service`, hotkey, виджет).
- Что умеет, что не умеет.
- Как поставить вопросы / сообщить об ошибке.

**Не путать с dev-README.** Пользовательское — отдельно.

### 3. «Не позориться» — базовые команды

Проверено вживую. Каждая команда **работает**:
- «Аура, который час» / «сколько времени».
- «Аура, какая погода в Москве».
- «Аура, расскажи историю про космос».
- «Аура, какие вкладки открыты».
- «Аура, найди вкладку макс».
- «Аура, открой ВК».
- «Аура, следующий рабочий стол».
- Hotkey паузы.
- Виджет статуса.

Если **хотя бы одна** из этих команд в живом прогоне **позорится** —
бета не готова. (Оговорка: T-one-ослышки — известная боль, не
блокер, если при 2-3 повторах Аура всё-таки понимает.)

### 4. Стабильность — не падает сутки

- `aura.service` запущен **больше 24 часов** без перезапуска.
- Нет `Restart=on-failure` в логе за сутки.
- RAG-память не растёт линейно (не течёт).

**Критерий проверки:** `systemctl --user status aura.service` →
`Active: active (running) since <24+ hours ago>`.

### 5. Тесты — 100% зелёные

- `pytest tests/` → **0 failed**.
- Не важно, сколько именно. Важно — все зелёные.

### 6. Секреты — вне git

- `vk_token.txt` в `.gitignore`.
- Или — в `~/.config/aura/vk_token` (chmod 600).
- `vault.json` в `.gitignore` (уже сделано — `471222a`).

**Критерий проверки:** `git log -p | grep -i "token"` → не находит
реальных токенов.

### 7. Бэкапы системы

- **Не только git.** Git — код. А конфиги:
  - `~/.config/systemd/user/aura.service`
  - `~/.config/pipewire/pipewire-pulse.conf.d/`
  - `~/.local/state/wireplumber/default-nodes`
  - `~/.config/kglobalshortcutsrc`
- Скрипт `contrib/backup_configs.sh` — собирает всё в `~/aura_backup_YYYYMMDD.tar.gz`.

**Критерий проверки:** скрипт запущен, архив восстановлен на тесте.

### 8. Документация — актуальна

- ADR 001..010 актуальны.
- `migration-roadmap.md` — не старше недели.
- `JOURNAL.md` — последняя запись не старше 3 дней.

### 9. Логи — читаемы

- `journalctl --user -u aura.service` → понятные сообщения.
- Ошибки **без стектрейсов**, если это не dev-режим.
- Уровни: `INFO` для обычных, `WARNING` для проблем, `ERROR` для падений.

**Не критично для беты, но желательно.**

### 10. Healthcheck

- Аура пишет `/tmp/aura_status.json` **раз в цикл**.
- systemd может проверить: если файл не обновлялся 60 сек — рестарт.
- Опционально: `aura.service` c `WatchdogSec=60`.

## Что НЕ считаем обязательным для беты

- ❌ Кросс-платформенность (Windows/Mac).
- ❌ Мобильное приложение.
- ❌ Barge-in (отложено, ADR-009).
- ❌ «Продолжи вчерашнее» (Фаза 11).
- ❌ Карточка диалога в виджете (Фаза 9.3.2).
- ❌ Публикация в Flathub/AUR.
- ❌ CI/CD (GitHub Actions).
- ❌ Мониторинг (Grafana/Prometheus).

Это — **после беты**. Не путать.

## Правила работы (после этого ADR)

Это **реакция на аудит сессии 2026-09-23**: мы иногда нарушали
small batch, YAGNI, бэкап перед правками. Фиксируем правила.

### 1. Small batch — святое

- Один коммит = **одно** изменение.
- Коммит <200 строк diff (кроме рефакторинга).
- Коммит сразу после зелёных тестов.
- **Не** смешивать фикс + фичу + рефакторинг.

### 2. Тесты до коммита

- `pytest tests/` зелёные — **до** `git commit`.
- Никогда «закоммичу, потом починю тесты».
- Если тесты упали — **фикс тестов в том же коммите**, не отдельным.

### 3. Бэкап перед system-правкой

- Перед правкой **любого** файла вне `~/aura_project/`:
  - `cp файл файл.bak.$(date +%s)` в `/tmp/`.
  - Потом правка.
  - Потом проверка.
- **Это правило после истории с kglobalshortcutsrc** (23 сент).

### 4. JOURNAL в том же коммите

- Не задним числом.
- Не отдельным «docs: journal».
- **В том же коммите**, что код.
- Если код без JOURNAL — неполный коммит.

### 5. Roadmap — живой

- Обновляем **при каждом закрытии фазы**.
- Не реже **раза в неделю** проверяем актуальность.

### 6. Один фокус в сессии

- Одна сессия = одна крупная тема.
- Не «сегодня barge-in, потом виджет, потом hotkey».
- Если тема оказалась больше — **разбить на под-сессии**.

### 7. Slow is smooth, smooth is fast

- Торопливость → откаты → потеря времени.
- Неторопливость → работа с первого раза → выигрыш.
- **Это правило после barge-in (провал дважды).**

## Последствия

### Положительные

- Чёткий критерий «мы готовы» — не «ещё чуть-чуть».
- Дисциплина работы фиксирована.
- Уроки сессий 18-23 сент формализованы.

### Отрицательные

- Возможно, бета **отложится** — если критерии не выполнены.
- Это **правильно**: лучше отложить, чем выпустить сырое.

### Риски

- Критерии могут быть **слишком строгими** — тогда скорректируем.
- Критерии могут быть **слишком мягкими** — тоже скорректируем.
- ADR-010 — **живой документ**. Может быть пересмотрен.

## Проверка готовности к бете

Скрипт `contrib/check_beta_ready.sh`:
- Проверяет все 10 критериев.
- Возвращает **OK** или **список невыполненных**.

**Создадим в отдельной задаче** (Фаза 12).
