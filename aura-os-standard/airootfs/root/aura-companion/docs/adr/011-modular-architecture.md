# ADR-011: Модульная архитектура

## Дата
2026-09-24

## Статус
Принято

## Контекст

Vision 2.0 (docs/vision.md) определила три аудитории:
люди с особенностями, люди с ментальными особенностями, все.

Каждая аудитория нуждается в **разном наборе** агентов:
- Базовый — время, погода, музыка, столы.
- Мессенджеры — Макс, Telegram, WhatsApp.
- Медицинский — память состояния, возврат к задаче.

Сейчас `bootstrap.py` регистрирует **всех 25 агентов** явно.
Это работает, но:
- Нельзя отключить ненужное.
- Нельзя добавить модуль без правки bootstrap.
- Разные пользователи получают одинаковый набор.

## Решение

### 1. Атрибуты модуля в BaseAgent

Каждый агент получает **метаданные**:

    MODULE_NAME: str = "base"           # имя модуля
    MODULE_DESCRIPTION: str = ""        # краткое описание
    MODULE_REQUIRES: tuple = ()         # зависимости (другие модули)
    MODULE_ALWAYS: bool = False         # всегда включён (ядро)

Никаких новых методов — только атрибуты. Open-Closed Principle:
класс открыт для расширения, но не требует правки наследников.

### 2. Конфиг пользователя

Файл: `~/.config/aura/modules.toml`

    [modules]
    # Base — всегда включено
    # messenger = false
    # medical = false
    # vision = true
    # vk_music = true

- Ключа нет → default (MODULE_ALWAYS решает).
- Ключ `true` → принудительно включить.
- Ключ `false` → принудительно отключить.

### 3. bootstrap.py читает конфиг

    modules_config = load_modules_config()   # dict[str, bool]
    for agent_class in ALL_AGENT_CLASSES:
        if is_module_enabled(agent_class, modules_config):
            orch.register(agent_class())

`is_module_enabled`:
- Если `MODULE_ALWAYS` → True.
- Если ключ в конфиге → значение.
- Иначе → default (False для опциональных).

### 4. Обратная совместимость

- Конфига нет → все `MODULE_ALWAYS` включены, остальные **тоже** включены
  (сохраняем текущее поведение до первой правки конфига).
- После создания конфига → строгий режим.

### 5. GUI (в планах, Фаза 15)

Приложение читает `MODULE_*` из реестра агентов,
рисует чекбоксы, пишет `modules.toml`.

## Обоснование

- **Unix philosophy** (Мак-Илрой, 1978). Модули, собираемые в систему.
- **Open-Closed Principle** (Мартин, SOLID, 1996). Расширение без правки ядра.
- **Privacy by Design** (Гдански, 2011). Модуль выключен → данных нет.
- **YAGNI** (Джеффрис, XP). Не пишем больше, чем нужно сейчас.
- **Home Assistant** — доказанная модель: ядро бесплатное, модули
  включаются по выбору.

## Последствия

### Положительные

- Пользователь контролирует, что активно.
- Три аудитории получают разные наборы из одного кода.
- GUI сможет управлять модулями без правки кода.
- Тесты изолированы: тестируем модуль — не тестируем чужие.

### Отрицательные

- `bootstrap.py` усложняется (фильтрация).
- Агенты должны иметь корректные `MODULE_*` — иначе не включатся.
- Отладка сложнее: «почему не сработало?» — модуль выключен?

### Риски

- Забыть добавить `MODULE_NAME` новому агенту → он «прилипнет» к base.
  Митигация: тест, проверяющий, что у каждого агента есть MODULE_NAME.
- Пользователь отключит ядро (например, `journal`) → Аура сломается.
  Митигация: `MODULE_ALWAYS = True` для критичных.

## Реализация

1. `BaseAgent` — добавить 4 атрибута.
2. Все 25 агентов — заполнить `MODULE_*`.
3. `bootstrap.py` — читать `modules.toml`, фильтровать.
4. Тесты — 7–8.
5. Живой прогон: default и с выключенным модулем.
