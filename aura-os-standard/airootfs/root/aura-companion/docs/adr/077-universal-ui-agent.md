# ADR-077: Universal UI Agent

**Дата:** 2026-10-02
**Статус:** Proposed (разведка завершена)

## Контекст

Пользователь описывает желаемое поведение:
- «Аура, открой ВК» → открывает
- «Аура, открой сообщения» → находит кнопку, нажимает
- «Аура, напиши Ивану: встреча в 14-00» → пишет в поле, **спрашивает перед отправкой**
- Работает на **любом сайте и системном UI**, где пользователь видит кнопки

Это уровень Anthropic Computer Use / OpenAI Operator, но **локальный** и
**интуитивный**: Aura понимает намерение и действует через UI.

## Что уже есть

| Компонент | Роль | Готовность |
|---|---|---|
| `at_spi.py` | Accessibility tree Linux-приложений | есть, не в registry |
| `screen_reader.py` | Чтение окон/экрана | есть, не в registry |
| `vision.py` | Vision-агент | есть, не в registry |
| `browser_tabs.py` + Firefox bridge | Управление вкладками | работает |
| `content_vk.js`, `content_whatsapp.js` и др. | DOM-скрипты | работает |
| `vk_web.py`, `vk_music.py` | Специфика VK | работает |

## Решение (черновик)

Три слоя, graceful degradation:

    Слой 3: LLM (qwen2.5) — понимает намерение «открой сообщения»
       ↓
    Слой 2: Locator — находит элемент (AT-SPI / DOM / Vision OCR)
       ↓
    Слой 1: Actor — click / type / scroll / submit

Ключевые принципы:
- **Подтверждение перед опасным**: отправка, покупка, удаление → user confirm
- **Локально**: скриншоты не уходят в облако
- **YAGNI**: MVP = 1 сценарий (VK: напиши Ивану)
- **Graceful degradation**: AT-SPI → DOM → Vision (в этом порядке)

## Границы (YAGNI)

НЕ делаем в MVP:
- Полноценный VLM с нуля
- Electron / собственный браузер
- Кроссплатформенность (только Linux + Firefox)
- Автономное исполнение без подтверждения

## ToC

Узкое место — точность распознавания кнопок.
MVP тестируем на: **1 сайт (VK) + 1 системное окно**.

## Pareto

80% ценности — браузер (VK, WhatsApp, Telegram — bridge есть).
20% — системный UI (настройки, файловый менеджер).

## Разведка (2026-10-02)

**AT-SPI на Wayland:** `pyatspi` и `gi Atspi` не установлены. `xdotool` (X11),
`ydotool` (Wayland) есть. AT-SPI требует установки + проверки на Wayland
(скорее всего не работает или работает частично).

**Vision OCR:** `maim` + `tesseract` (rus+eng) уже используются в `screen_reader.py`.
`vision.py` (pyautogui) — X11 only, на Wayland отключён.

**Firefox bridge:** работает. `content_vk.js` умеет click, querySelector,
input.dispatchEvent. `vk_web.py` — 14 action. **Это MVP-путь.**

**Tool router:** `qwen2.5:7b-instruct-q4_K_M` через Ollama, tool calling.
Уже есть system_prompt и реестр tools.

## Решение (уточнено)

MVP UI Agent = **Firefox bridge + LLM routing** для одного сценария:
«Аура, напиши Ивану: <текст>».

Не в MVP:
- AT-SPI системный UI (позже, отдельный эпик)
- Vision OCR для click (только для чтения сейчас)
- Кроссплатформенность

## Открытые вопросы (обновлено)

1. Как искать диалог по имени в VK DOM? (нужен селектор + поиск)
2. Подтверждение перед отправкой — через FSM (awaiting_confirm уже есть)
3. Формат «элемента» — DOM-селектор + человекочитаемое имя

## Последствия

- Aura получает «глаза и руки» → новый класс задач
- Требует аккуратности: ошибочный клик = проблема
- Нужен undо-лог (что кликнули, где) для отладки
