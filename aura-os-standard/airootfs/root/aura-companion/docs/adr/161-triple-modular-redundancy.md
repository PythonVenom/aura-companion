# ADR-161: Triple Modular Redundancy (P3 #157)

**Дата:** 2026-10-14  
**Статус:** Accepted  
**Контекст:** P3, космические задачи. Вдохновлено TMR (von Neumann, 1956).

## Проблема

Критичные агенты AURA (SOS, Fall, Meds) должны отказывать безопасно.
Единичный логический сбой или SEU (single-event upset) в одной реплике
не должен привести к ложному решению (например, пропуск вызова помощи).

## Решение

Модуль `aura/core/tmr.py`:

- **`TripleModularRedundancy(replicas=3)`** — N реплик (нечётное, >=3).
- **`run(task)`** — вызывает task N раз, majority vote по ключу результата.
- **`TMRStats`** — total/agreed/disagreed/failed + agreement_rate().
- **`TMRError`** — нет большинства или все реплики упали.

## Обоснование

- **Почему N нечётное и >=3:** чётное даёт ничью; N=1 не даёт избыточности.
- **Почему голосование по ключу, а не по объекту:** unhashable результаты
  (dict) приводятся через repr — стабильно для большинства кейсов.
- **Почему все реплики в одном процессе:** первый шаг. Для настоящей
  космической отказоустойчивости нужны изолированные процессы/железо.

## Последствия

**Плюсы:**
- Маскирование одиночного отказа.
- Метрика agreement_rate() → в stress.db для мониторинга.
- Готово к интеграции с критичными агентами (SOS, Fall).

**Минусы:**
- Тройной расход CPU на критичных задачах.
- Python GIL — реплики не параллельны, только логически независимы.
- Не защищает от системных сбоев (падение процесса, ОС).
