# ADR-012: Dialog FSM — многошаговый диалог без активации

## Дата
2026-09-25

## Статус
Принято

## Контекст

Messenger работает одной фразой: «Аура, напиши Петруха: привет» → ввод + «отправь».

**Проблемы:**
1. **T-one режет длинные фразы.** «напиши сообщение петруха привет из будущего» → «напиши сообщ» или «напиши петру».
2. **Двоеточие не всегда распознаётся.** Голосом «:» — сложно.
3. **Пользователь хочет диалог.** «Аура, открой чат Петруха» → «Что написать?» → «привет» → «Написала. Отправить?» → «да».

**Что нужно:** многошаговый диалог **без повторной активации «Аура»** на каждом шаге.

## Решение

**Конечный автомат (FSM) состояний диалога.**

### Состояния

```
IDLE              — ждём «Аура ...» (обычный цикл)
ASK_TEXT          — открыт чат, ждём текст сообщения
ASK_CONFIRM       — текст введён, ждём «отправить?/да/нет»
```

### Переходы

```
IDLE:
  «Аура, открой чат X в максе»   → messenger.find_chat
                                  → ASK_TEXT (спрашиваем «Что написать?»)

ASK_TEXT:
  (без «Аура») любой текст        → messenger.send_message(chat, text)
                                  → ASK_CONFIRM («Написала: X. Отправить?»)
  (без «Аура») «отмена» / таймаут → IDLE
  «Аура ...»                      → СБРОС → IDLE → новая команда

ASK_CONFIRM:
  (без «Аура») «да/отправь/ок»    → messenger.finalize_send
                                  → IDLE
  (без «Аура») «нет/отмена»       → messenger.clear_input
                                  → IDLE
  (без «Аура») другой текст        → игнорируем (ждём да/нет)
  «Аура ...»                      → СБРОС → IDLE → новая команда
  таймаут (30 сек)                → IDLE (не отправляем)
```

### Таймауты

- ASK_TEXT: **30 секунд**. Не сказал — отмена.
- ASK_CONFIRM: **30 секунд**. Не подтвердил — **не отправляем** (безопасность).

### Где живёт

`AuraOrchestrator` — атрибуты:
- `_dialog_state`: `"idle" | "ask_text" | "ask_confirm"`
- `_dialog_chat`: имя чата (для context)
- `_dialog_text`: введённый текст (для показа)
- `_dialog_deadline`: `time.time() + 30`

### Как работает главный цикл

```
while self.running:
    if self._dialog_state == "ask_text":
        # Слушаем БЕЗ «Аура».
        heard = listener.listen(timeout=5)
        if heard:
            if self._is_cancel(heard):
                reset_dialog()
            elif self._is_aura(heard):
                reset_dialog()  # новая команда через обычный путь
            else:
                # Это текст сообщения.
                send_message(chat, heard)
                state = "ask_confirm"
        if now > deadline:
            reset_dialog()
        continue  # не идём в обычный цикл

    if self._dialog_state == "ask_confirm":
        # Слушаем БЕЗ «Аура».
        heard = listener.listen(timeout=5)
        if heard:
            if self._is_yes(heard):
                finalize_send()
                reset_dialog()
            elif self._is_no(heard) or self._is_cancel(heard):
                clear_input()
                reset_dialog()
            # другой текст — игнор
        if now > deadline:
            reset_dialog()  # НЕ отправляем
        continue
```

### Как messenger сообщает о переходе

Messenger — **stateless**. Он возвращает **маркер в ответе**:

```
"🌐 Открыла чат X. Что написать? [FSM:ask_text:X]"
```

Или **через `data` в AgentResponse**:

```python
return AgentResponse.ok(
    text="Открыла чат X. Что написать?",
    agent_name=self.name,
    data={"fsm_state": "ask_text", "chat": query}
)
```

**Решение: через `data`** — чище, не парсим текст.

`AuraOrchestrator` после `orch.process(cmd)`:
- Если `response.data.get("fsm_state")` есть → перейти в это состояние.
- Иначе → IDLE.

### Отмена явная

Голосом: **«отмена»** или **«стоп»** — в любом состоянии → IDLE.
Не отправляем при таймауте.

### Перебивание активацией

Если в ASK_TEXT/ASK_CONFIRM услышим **«Аура»** — сбрасываем FSM и обрабатываем как новую команду.

## Обоснование

- **FSM** — стандартный паттерн для диалоговых систем (Rasa, Dialogflow, Voiceflow).
- **Таймауты** — безопасность. Ничего не отправляем без явного «да».
- **Без активации** — UX: пользователь не говорит «Аура» на каждом шаге.
- **Через `data`** — не парсим текст ответа, работаем со структурой.

**Ссылки:**
- Jurafsky & Martin, «Speech and Language Processing», 3rd ed. — глава о dialogue management.
- Rasa documentation — формы и слоты.
- Cockburn, «Hexagonal Architecture», 2005 — FSM не знает про агентов.

## Последствия

**Положительные:**
- Многошаговый диалог без активации.
- Безопасность: таймаут → не отправляем.
- Расширяемо: новые FSM-сценарии (подтверждение удаления, poweroff и т.д.).

**Отрицательные:**
- `aura_main.py` усложняется.
- Тесты: нужны интеграционные на все переходы.
- Риск: если пользователь говорит не то — FSM может «застрять». Митигация: таймаут 30 сек + «отмена».

**Риски:**
- T-one режет текст сообщения («привет из будущего» → «привет из буд»). Отправляем что услышали. Пользователь может отменить.
- Долгая фраза в ASK_TEXT: T-one может распознать как команду. Митигация: в ASK_TEXT не ищем «Аура» / keywords, только текст.

## Что НЕ делаем

- Не делаем полноценный слот-filling (Rasa-style). Только **2 слота**: чат + текст.
- Не добавляем память между сессиями. FSM в RAM, при перезапуске сбрасывается.
- Не делаем вложенные FSM. Только линейный IDLE ↔ ASK_TEXT ↔ ASK_CONFIRM.

## Реализация

1. `messenger.py` — добавить `data={"fsm_state": ..., "chat": ...}` в ответы.
2. `aura_main.py` — FSM-логика в главном цикле.
3. Тесты: `test_dialog_fsm.py` — 8–10 тестов.
4. Живой прогон: полный сценарий.
