# ADR-015: Calendar from Chats — календарь из чатов

## Дата
2026-09-26

## Статус
Принято

## Контекст

Ты общаешься в Максе, Telegram, WhatsApp. В чатах **всегда есть события**:
- «Давай в среду в 15:00 на массаж».
- «Встреча перенесена на пятницу 11:00».
- «Созвон в 18:30».
- «С днём рождения! 15 мая».

Сейчас **Аура это не видит**. Ты **сам** вручную вносишь в календарь KDE.

**Идея:** Аура **автоматически** извлекает события из чатов. С подтверждением. С записью в календарь.

**Польза:**
- Не надо помнить — Аура подскажет.
- Не надо вручную писать — Аура вносит.
- События не теряются в потоке чатов.
- Утренний брифинг показывает план на день.

**Что говорит наука:**
> **Event Extraction from Text** — NLP-задача (Grishman, 2019). Требует: NER (Named Entity Recognition) + RE (Relation Extraction) + Temporal Tagging.

## Решение

**Трёхэтапный pipeline: извлечение → подтверждение → запись.**

### Pipeline

```
1. Сбор
   Content script (Макс) → новые сообщения → Ауре.

2. Извлечение
   LLM (Ollama qwen2.5) + prompt:
     «Извлеки события из текста. Формат JSON:
      {date, time, title, source}».
   Fallback: regex (даты, время, «встреча/созвон/массаж»).

3. Дедупликация
   Если событие уже в календаре — пропустить.

4. Подтверждение
   Аура: «Из чата с Иваном: «Встреча в пятницу 11:00».
         Добавить в календарь?»
   Пользователь: «да» / «нет».

5. Запись
   Опционально:
   - Локальный JSON (~/.config/aura/calendar.json).
   - Или KDE KOrganizer через DBus/ICS.
```

### Формат события

```python
@dataclass
class Event:
    date: str           # "2026-09-30"
    time: str           # "11:00" или ""
    title: str          # "Встреча с Иваном"
    source: str         # "max:petruha_chip"
    raw: str            # оригинальный текст
    confirmed: bool     # пользователь подтвердил
    uid: str            # уникальный ID (для дедупликации)
```

### Дедупликация

**Проблема:** одно событие в 3 сообщениях. **Не надо 3 раза добавлять.**

**Решение:** хеш события = `sha1(date + time + title.lower()[:20])`. Если есть — пропустить.

### Окно анализа

**Не весь чат, а:**
- **Последние 50 сообщений** при открытии чата.
- **Новые** сообщения (MutationObserver).
- **Мои фразы** не парсим — только **входящие**.

### Подтверждение обязательно

**Правило:** никогда не пишем в календарь без «да».

**Причины:**
- LLM может ошибиться (дата, время).
- Событие может быть шуткой.
- Может быть **не тебе** («встреча у Пети»).

**Формат:** «Из чата с X: «...». Добавить в календарь на [дата]?».

### Что **не** парсим

- **Дни рождения** — можно, но отдельная задача.
- **Напоминания себе** — только если явно.
- **Прошлые** события (дата < сегодня).
- **Фразы без даты** — «давай встретимся» — бесполезно.

## Архитектура

### Модуль `aura/agents/calendar.py`

```python
class AgentCalendar(BaseAgent):
    name = "calendar"
    KEYWORDS = (
        "какие планы", "что в календаре", "добавь в календарь",
        "планы на день", "расписание",
    )
    def add_event(self, event: Event) -> str: ...
    def list_events(self, date: str) -> list[Event]: ...
    def parse_message(self, text: str, source: str) -> list[Event]: ...
```

### Модуль `aura/agents/calendar_extractor.py`

```python
class CalendarExtractor:
    """LLM + regex извлечение событий."""
    def extract(self, text: str) -> list[Event]:
        # 1. Regex (быстро, для явных форматов).
        # 2. LLM (медленно, для сложных фраз).
        # 3. Дедупликация.
        ...
```

### Интеграция с Максом

**Content script** (`content_max.js`):
- MutationObserver на новые сообщения.
- При новом сообщении → `browser.runtime.sendMessage({action: "max_new_message", text: ...})`.
- Background.js → host → Аура.

**Аура:**
- Получила сообщение.
- Пропустила через `CalendarExtractor`.
- Если есть событие → подтверждение.
- Если «да» → запись в `~/.config/aura/calendar.json`.

## Хранение

**Первый вариант:** локальный JSON.

```json
{
  "events": [
    {
      "uid": "abc123",
      "date": "2026-09-30",
      "time": "11:00",
      "title": "Встреча с Иваном",
      "source": "max:petruha",
      "raw": "давай в пятницу 11:00",
      "confirmed": true,
      "created": "2026-09-26T20:00:00"
    }
  ]
}
```

**Файл:** `~/.config/aura/calendar.json`, `chmod 600`.

**Второй вариант (позже):** экспорт в KDE KOrganizer (`.ics` формат).

**Почему не сразу KOrganizer:**
- Сложно тестировать.
- DBus-вызовы хрупкие.
- Начнём с простого.

## Обоснование

- **Event Extraction** — Grishman, 2019; стандартная NLP-задача.
- **LLM + regex** — гибрид (быстро + точно).
- **Подтверждение** — privacy-by-design, безопасность.
- **Локально** — односторонний шлюз (ADR-005).
- **Поэтапно** — JSON → KOrganizer.

## Последствия

### Положительные
- События не теряются в чатах.
- Утренний брифинг показывает **реальные** планы.
- Автоматизация рутины.
- Уникально на рынке.

### Отрицательные
- LLM может ошибиться (митигация — подтверждение).
- Нужно отключать для нежелательных чатов.
- Хрупкость: если Макс меняет DOM, парсер ломается.

### Риски
- **Ложные события.** Митигация: подтверждение перед записью.
- **Пропуск событий.** Митигация: regex-fallback.
- **Утечка.** Всё локально, файл `chmod 600`.
- **Спам от чатов.** Митигация: только выбранные чаты.

## Что НЕ делаем

- **Автозапись без подтверждения.** Никогда.
- **Синхронизация с Google Calendar.** Никогда (облако).
- **Парсинг всех чатов.** Только выбранные.
- **Дни рождения автоматически.** Отдельная задача.
