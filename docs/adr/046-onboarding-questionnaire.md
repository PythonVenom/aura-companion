# ADR-046: Onboarding Questionnaire (RPG-style)

**Дата:** 2026-09-28
**Статус:** Принято
**Связано:** ADR-019 (Installation), ADR-023 (Voice Customization), ADR-040 (Voice Profiles)

## Контекст

Config wizard (5 вопросов) покрывает базовое: имя, обращение, стиль, юмор, голос.
Для «Aura как друг» нужно больше: пол пользователя (влияет на род обращений),
пол/род Aura, роль, имя пользователя. Это RPG-подход: игрок создаёт персонажа.

## Решение

### Онбординг = создание персонажа

Расширить `config_wizard.run()` до 9 вопросов в 3 группах:

**Группа 1 — Пользователь:**
1. Имя пользователя
2. Пол пользователя (м/ж/нейтр) → влияет на род обращения
3. Обращение: ты/вы

**Группа 2 — Аура:**
4. Имя Aura
5. Пол/род Aura (она/он/они/нейтр)
6. Роль: ассистент / друг / наставник / муза / дворецкий / свой
7. Характер: тёплая / саркастичная / формальная / детская / мудрая

**Группа 3 — Голос:**
8. Тон: кратко / развёрнуто
9. Голос TTS: женский / мужской / детский

Все ответы → `settings["persona"]`. Один раз ответил → навсегда.

### persona.py — сборка системного промпта

`aura/persona.py:build_system_prompt(persona) -> str` собирает текст для LLM:
- «Ты — {name}, {role}. Характер: {style}. Обращайся к {user_name} на {address}.
  Отвечай {tone}. {humor ? шути : не шути}.»
- Fallback: если поле пустое — дефолт (Aura/друг/тёплая/ты)

### Что НЕ делаем (YAGNI)

- Отдельный UserProfile dataclass — работаем со словарём `settings["persona"]`
- GUI-онбординг (в v1.0.1 — CLI, GUI в v1.0.2)
- Ветвление логики агентов по полу — только формат промпта
- Хранение persona в разных местах — только `settings.json`

## Последствия

- `config_wizard.run()` расширяется до 9 вопросов, старые ответы сохраняются
- `persona.build_system_prompt()` — единая точка сборки промпта
- Тесты: 10+ кейсов на маппинг persona → prompt
- Женский/мужской род в промпте — через явные строки, без сложной морфологии

## Открыто (v1.0.2)

- Графический онбординг (3 экрана, большие кнопки)
- Голосовой онбординг («представься сама»)
