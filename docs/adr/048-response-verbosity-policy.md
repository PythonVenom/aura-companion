# ADR-048: Response Verbosity Policy

**Дата:** 2026-09-28
**Статус:** Принято
**Связано:** ADR-013 (Dialogue Manager), ADR-040 (Voice Profiles)

## Контекст

Aura озвучивает **каждый** ответ агента. Для команд с очевидным
сенсорным результатом («следующий трек», «громче») это шум:
пользователь слышит подтверждение поверх того, что и так слышит.

Пример UX-паттерна: голосовые ассистенты (Алиса, Siri) не комментируют
действия, результат которых сенсорно очевиден.

## Решение

### Принцип: silent for self-evident

Агент **сам** решает, нужно ли озвучивать результат:

- **silent=True** — действие сенсорно очевидно (слышно/видно)
- **silent=False** (default) — пользователь должен знать (таймер, ошибка, инфо)

### Реализация

1. `AgentResponse` + поле `silent: bool = False`
2. `AgentResponse.ok(..., silent=False)` — новый параметр
3. `Orchestrator.last_silent()` — метод, читает последний silent
4. Pipeline (`aura_main.py`): `if not orch.last_silent(): speaker.say()`
5. Текст **всегда** идёт в `print()` + лог, silent влияет **только** на TTS

### Первая партия агентов (эта ADR)

- `music_local`: next_track, prev_track, pause, resume, stop → silent=True
- Остальные не трогаем — YAGNI, расширим по мере UX-тестов

### Что НЕ делаем

- Глобальный `settings["silent"]` — семантика должна быть на агенте
- Префикс `[[SILENT]]` в тексте — хак, отклонён
- Убирать `print()` — CLI продолжает показывать ответ

## Последствия

- Пользователь слышит голос только там, где это нужно
- Агенты **знают** про UX-семантику своих действий
- Тесты: `tests/test_response_silent.py` — 8 кейсов
- Дальше: `audio_pult` (громкость), `focus_switch`, `app_launcher`
