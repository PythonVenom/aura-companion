# ADR-052: ASR Sample Rate Matching

**Дата:** 2026-09-28
**Статус:** Принято

## Контекст

T-one streaming (sherpa-onnx) обучен на **16 kHz**.
listener.py в конфиге стоял `sample_rate = 8000`.

Симптом: 40-50% распознаваний с ошибками:
- «аура» → «аро», «аон»
- «таймер» → «тайна»
- «фаерфокс» → «эрфокс»

Причина: 8 kHz аудио кормили в модель, ожидающую 16 kHz.
Сдвиг частот ×2 — модель слышала «половину спектра».

## Решение

- `listener.sample_rate = 16000` (совпадает с обучением T-one)
- Env override `AURA_ASR_SR` для отладки
- `blocksize = 480` (30 ms при 16 kHz)
- `left_padding = 4800` (300 ms)
- `tail_padding = 9600` (600 ms)

## Результат

Live-тест: 95%+ чистых распознаваний (было ~40%).

## Последствия

- Правило: sample_rate модели = sample_rate capture.
- Проверка при смене ASR-модели обязательна.
- Env override для A/B-тестов.
