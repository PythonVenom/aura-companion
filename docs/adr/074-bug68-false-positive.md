# ADR-074: Bug 68 — false positive (sherpa resampler)

**Дата:** 2026-10-02
**Статус:** Принято

## Контекст

Bug 68: в journal каждые 8 сек `Creating a resampler: in=16000 out=8000`.
Гипотеза: модель T-one ждёт 8kHz, listener подаёт 16kHz — конфликт с ADR-052.

## Эксперимент

Drop-in `AURA_ASR_SR=8000`:
- resampler в sherpa: 13 → 0 за 30 сек
- CPU: 19% → 36% (регрессия ×1.9)
- PipeWire ресемплит 44100→8000 сам, дороже чем внутренний sherpa

## Решение

- ADR-052 ПРАВИЛЬНЫЙ: T-one принимает 16kHz на входе.
- sherpa сам ресемплит 16→8 внутри — это фича, не баг.
- Лог шумный, но CPU без ресемплера ВЫШЕ. Не трогаем.
- Drop-in откачен.

## Последствия

- Bug 68 закрыт как false positive.
- Если в будущем будем менять модель ASR — повторить A/B замер CPU.
- Кандидат: уменьшить verbosity sherpa (не наш уровень, C++).
