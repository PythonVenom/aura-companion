# ADR-109: Post-Release Review (PRR)

**Статус:** Accepted
**Дата:** 2026-10-02
**Verified:** будет при первом применении

## Контекст

После каждого релиза теряется контекст: что сломалось, что улучшилось,
где мы относительно рынка. Без ритуала проект слепнет.

## Решение

После каждого `git tag vX.Y` — обязательный PRR из 5 шагов:

1. **METRICS** — `scripts/prr/metrics.sh`
2. **SWOT-AURA** — честно, без натяжки
3. **BUG-HUNT** — 4 категории (bugs/security/arch/ux)
4. **TREND-RADAR** — 8 трендов, ≥3 должны быть 🟢 ahead
5. **ACTIONS** — таблица в vX.Y+1

Артефакт: `docs/reviews/vX.Y-review.md`.
Carma-скоринг (ADR-109): бейдж в README.

## Корректировка вектора (плазма-режим)

Пять принципов, чтобы быть «плазмой» — адаптивной системой:

1. **ADR после кода** — Verified: `<commit>`
2. **Патчи идемпотентны** — `scripts/patches/_lib.py`
3. **Тесты в том же коммите** — pre-commit hook
4. **Auto-reload расширения** — `scripts/firefox_reload.sh`
5. **Тег только через гейт** — `scripts/release.sh`

## Последствия

- (+) видимость: цифры, SWOT, тренды на каждой итерации
- (+) дисциплина: тег только зелёный, ADR только после кода
- (+) адаптивность: 5 плазма-принципов → меньше ручной работы
- (−) +30–60 мин на релиз
- (−) требует дисциплины — иначе превратится в ритуал ради ритуала
